# Support

## Where to Ask

Use GitHub Issues for reproducible bugs, documentation gaps, and narrowly scoped enhancement proposals. Use the issue templates so maintainers can evaluate authorization impact, containment implications, and validation evidence efficiently.

Use GitHub Discussions, when enabled, for usage questions, design exploration, integration patterns, and community knowledge sharing. Do not publish credentials, target details, customer information, raw evidence, or live engagement data in either Issues or Discussions.

## Security Reports

Do **not** open a public issue for a suspected vulnerability, policy bypass, containment failure, token exposure, or unsafe default. Follow the private reporting process in [SECURITY.md](SECURITY.md).

## Before Opening an Issue

Read [RESPONSIBLE_USE.md](RESPONSIBLE_USE.md), the relevant runbook, and [CONTRIBUTING.md](CONTRIBUTING.md). Include the project version, sanitized environment details, safe reproduction steps, expected and actual behavior, and the validation you already performed. Never include target inventories, access material, or unredacted evidence.
